# Game Design Document — A Long Journey

> 本文档是项目的 **设计宪法**：所有玩法、内容、美术、代码都应能回到"核心支柱"上。
> 写法原则：先定位，再定支柱，再定循环，再定系统，最后定范围。
> 凡是文档里没有写的，默认 **不做**。

---

## 0. 一句话定位 / Elevator Pitch

> **《A Long Journey》是一款 2D 等距像素风的"旅途求生 + 路线塔防"游戏。**
> 你是后启示录世界里独行的旅人，沿着一条破碎的大陆向前推进。
> 在每一个**营地节点**短暂停留：白天探索拾荒、夕阳下规划路线与防御工事、夜晚抵御异常潮汐；
> 在路上**收留同行者**、点亮地图、解开这片土地"很久以前发生过什么"的谜底。

把它想成：**Loop Hero 的旅程结构 × Mindustry 的路线建造 × 饥荒的昼夜张力 × 无尽之剑的氛围**。

## 1. 核心体验 / Core Fantasy

| 阶段 | 玩家应该感受到的情绪 |
| :--- | :--- |
| **抵达新营地** | 孤独、荒凉、警惕|
| **白天忙碌** | 节奏感、专注|
| **黄昏倒计时** | 紧张、取舍|
| **夜晚抵御** | 高压、爽快|
| **天亮拔营** | 释然、沉淀 |
| **前往下一个目的地** | 未知、期待|

## 2. 核心支柱 / Core Pillars

> 任何新机制提案必须 **同时服务至少一条支柱**，否则砍掉。

1. **旅人，而非定居者 (Wayfarer, not Settler)**
   - 玩家是"经过"而不是"扎根"，游戏机制应使得**自然**并**向往**前往下一个据点。
   - 设计后果：地图分段、建造可拆解可继承、永久进度走"队伍/科技/世界知识"而非"建筑"。

2. **路线即玩法 (The Route Is the Game)**
   - 核心建造： **"资源点 → 工坊 → 防线 → 营火"** 的路径规划。
   - 设计后果：建筑以"节点 + 传送带/路径"为主，内外空间不分离，玩家始终在外部俯视。

3. **共同前行 (Together on the Road)**
   - 孤独是开局，**陪伴是奖励**。NPC、宠物、未来的多人都是同一句"沿途同行"的延伸。
   - 设计后果：收留 NPC = 解锁新工种 + 新对话 + 新风险；多人是"协作旅程"而非 PVP。

## 3. 核心循环 / Core Gameplay Loop

### 3.1 短期循环（一个营地，约 15–25 分钟）

```text
抵达营地 (Arrive)
   └─→ 勘察地形，标记资源点 (Scout)
        └─→ 拾荒 / 砍伐 / 击退散兵 (Gather & Skirmish)
             └─→ 铺设路线、放置工坊与防御 (Build Route)
                  └─→ 黄昏：补给与最后调整 (Prepare)
                       └─→ 夜潮：抵御 1–3 波异常 (Defend)
                            └─→ 黎明：清点战利品、修复路线 (Recover)
                                 └─→ 拔营，收取"营地成果"作为旅程库存 (Depart)
```

### 3.2 中期循环（一段旅程，约 3–5 个营地）

- 每段旅程有一个 **主题**（例：荒废铁路、被淹没的村镇、信号塔废墟）。
- 每个营地难度递增、生态变化、敌人组合变化。
- 终点 = 一座**纪念碑 / 信标**：玩家在这里可以选择**长休**（无尽模式？）。

### 3.3 长期循环（多段旅程，跨存档进度）

- 解锁新的科技节点（图纸、工坊、武器流派）。
- 永久同伴小队成长（最多 3 名 NPC 同行）。
- 世界观碎片（信件、壁画、广播）逐步拼合一个"很久以前发生了什么"的真相。

## 4. 玩家旅程 / First-Hour Experience

> 这一节直接对应 **MVP 切片**（见 §9）。

| 时长 | 玩家在做 | 我们想教他什么 |
| :--- | :--- | :--- |
| **0–2 min** | 在一段道路上醒来，跟随光点走到第一个营地。 | 移动（方向键）、视角、氛围。 |
| **2–6 min** | 跟随提示**点燃篝火**（首个存档点）、**砍第一棵树**、**捡石头**。 | 收集、热栏、存档锚点。 |
| **6–12 min** | 用木头做一段**路径**与一个**箭塔**；放置一个**工坊**。 | 建造预览、路线连接、电力/补给概念。 |
| **12–18 min** | 黄昏倒计时；遇到第一个 NPC 求救（可选救援）。 | 紧迫感、NPC 收留、风险/回报抉择。 |
| **18–25 min** | 第一个夜潮：2 波 Ghost/Robot 沿固定路径来袭。 | 塔防核心爽点。 |
| **25–30 min** | 黎明结算 → 拔营 → 第二个营地预告。 | 旅程感、循环闭合。 |

## 5. 玩法系统 / Gameplay Systems

> 优先级标注：**P0 = MVP 必须**、**P1 = 首发应有**、**P2 = 之后再说**。

### 5.1 移动与操作 (P0)
- **WASD / 方向键**：八向移动。
- **鼠标左键**：交互 / 攻击 / 拾取（语境敏感）。
- **鼠标右键**：取消 / 上下文菜单。
- **数字键 1–5**：切换热栏（已实现）。
- **B**：进入/退出 **建造模式**（拖拽放置）。
- **空格**：翻滚 / 闪避（P1）。
- 设计原则：**绝不做组合键**；任何操作都能在 5 秒内向新玩家解释清楚。

### 5.2 探索与地图 (P0–P1)
- 地图结构：**分段式手作 + 程序化点缀**（不做无限世界）。
  - 一段旅程 = 3–5 个**营地节点** + 节点之间一段**通行段**（线性或带 1 个分叉）。
  - 通行段可以放遭遇事件（受伤的 NPC、商人、可绕路的小遗迹）。
- 生态群落（biome）作为**美术与敌人组合**的换皮，**不**作为额外系统：
  - **MVP 仅 1 个生态**：枯林荒原。其他生态是 P2。

### 5.3 收集与背包 (P0)
- 沿用现有 `InventoryComponent` + 5 格热栏。
- 主资源（MVP）：**木材、石头、废金属、布料、电池**。
- 工具消耗耐久（P1，避免一上来就做）。
- 携带上限：**总格数 20**（用紧迫感逼玩家做取舍）。

### 5.4 建造系统 — "路线塔防" (P0 核心)
- **三类建造物**，**只有这三类**（MVP）：
  1. **节点 (Nodes)**：营火（存档）、工坊（合成）、储物箱、信标（终点）。
  2. **路径 (Paths)**：木板路、传送带（P1）。路径有方向，自动把资源从工坊送到塔。
  3. **防御 (Defenses)**：箭塔、陷阱、围栏。**消耗弹药 = 路径运来的资源**。
- 关键决策：**不做建筑内部空间**。所有建造都放在外部俯视世界里 —— 直接砍掉一整套室内地图、室内光照、进出门动画。
- 建造网格：**自由放置 + 软网格吸附**（不强制方块对齐，符合等距像素风格）。
- 拔营时建造物 **不带走**，但按一定比例 **回收材料 + 解锁后续旅程的"快速建造模板"**。

### 5.5 战斗与敌人 (P0)
- 已有：**Ghost**（飘行、近战）、**Robot**（机械、远程？）。
- MVP 敌人就这两种 + **1 个 Boss**（每段旅程末尾的"巡夜者"）。
- 战斗体感重点：**塔与玩家协同**，玩家负责补漏 + 拾取 + 紧急情况救场，**不是**一个人砍光。
- 死亡：回到上一个营火，丢失**未存入箱子的**热栏物品（P1：永久死亡是 stretch，不是默认）。

### 5.6 NPC 与同伴 (P1)
- **路上事件**：受伤的人、被困的工程师、流浪的孩子。救援后可邀请加入营地。
- 每个 NPC 有 **1 个工种**（樵夫 / 工程师 / 神枪手 / 治疗），自动协助：
  - 工程师能修路线、樵夫自动砍树、神枪手守塔、治疗回血。
- **同伴上限：3 人**。控制规模、控制 AI 复杂度。
- 长休时同伴有 **简短对话事件**，揭示世界观碎片。

### 5.7 科技与永久进度 (P1)
- 长休/通关一段旅程 → 解锁 **1–2 个新图纸** 或 **1 个新工种**。
- 科技树**扁平、横向**：不做"等级压制"，而是"流派切换"（路线流 / 陷阱流 / 同伴流）。

### 5.8 世界观叙事 (P1)
- 通过 **环境叙事**（壁画、残骸、机械尸体、广播片段）传达，**不做**长对话剧情。
- 总叙事疑问：**这片大陆为什么变成这样？我为什么要往前走？**
- 答案在最终旅程揭晓 —— MVP 不需要这部分。

### 5.9 多人 (P2)
- 已有 `PlayerRegistry` 与 `LocalPlayerContext` 在为联机做准备。
- 设计上：**协作 Co-op，不做 PVP**；分工天然契合工种系统。
- **MVP 仍以单人为主**，但所有系统设计要"假装将来会有第二个玩家"。

## 6. 美术与世界观 / Art & World

- **视角**：2D 等距 (isometric)，瓦片基础。
- **动画**：4 向（若制作时间太长转为 2 向） + 左右翻转。
- **基调**：低饱和、冷色为主、夕阳与火光是少数暖色高光。
- **氛围参考**：无尽之剑、Death Stranding（孤独的旅程感）、Tunic（神秘与不被解释的世界）。
- **音效优先于音乐**：风声、脚步、火堆噼啪、远处的金属呻吟。
- **UI**：极简。屏幕上常驻只有：热栏 + 血量 + 一个倒计时（黄昏/夜潮）。

## 7. 范围控制 / Scope（这一节才是这次重构的真正目的）

### 7.1 ✅ MVP 必做（垂直切片，目标：1 个完整旅程，3 个营地）
- 1 个生态（枯林荒原）+ 3 个手作营地地形。
- 5 种资源 + 5 种合成产物。
- 3 类建造物（节点/路径/防御），每类 2–3 个具体物件。
- 2 种普通敌人 + 1 个旅程末尾 Boss。
- 完整的"白天–黄昏–夜潮–黎明"循环。
- 1 名可救援 NPC（演示同伴系统）。
- 主菜单 / 存档 / 设置最小可用。

### 7.2 🟡 首发应有（MVP 之后、首个公开版本之前）
- 2–3 个生态。
- 同伴系统完整化（3 工种）。
- 科技/图纸解锁。
- 控制器支持。

### 7.3 🔴 明确不做 / Out of Scope
> 写下来是为了**抵御未来的"要不要顺便做一下…"**。

- ❌ **无限/巨型开放世界**（用分段旅程代替）。
- ❌ **建筑内部空间 / 室内场景**。
- ❌ **复杂工业链**（不做 Factorio/Mindustry 那种多层流体/电路）。
- ❌ **PVP / 竞技模式**。
- ❌ **角色捏脸 / 装备外观系统**。
- ❌ **多种族 / 多职业起手选择**（只有"旅人"一个开局）。
- ❌ **天气系统**（夜潮已经是天气替代品）。
- ❌ **复杂任务/对话树**（环境叙事 + 短对话即可）。

## 9. 风险与对策 / Risks

| 风险 | 影响 | 对策 |
| :--- | :--- | :--- |
| 等距像素动画工作量 | 高 | 4 向 + 镜像；NPC 共用骨架；Aseprite Wizard 已就位。 |
| 建造系统手感差 | 高 | **优先做手感原型**：放置预览 + 删除 + 路径连通；其他都靠后。 |
| 程序化地图调试地狱 | 中 | 改成**手作营地 + 程序化点缀**，控制变量。 |
| 多人架构过早抽象 | 中 | 接口在、实现先单人；遵循 `MultiplayerArchitecture.md`。 |
| 玩法太"杂" | 高 | **§2 的三条核心支柱是否决权**，新机制提案不过支柱就砍。 |

## 11. 待决问题 / Open Questions

> 这些是会**根本性影响开发量**的岔路，建议先一起定下来再开工。

**死亡惩罚 & 局内/局外**
   - A. 回到营火，掉热栏物品 | 类mc，沙盒向世界
   - B. 旅程失败，回到上一段长休点。| 一次存档点为一局，线性地图
   - C. 永久死亡。| roguelike 化，一次旅途为一局 

**旅程是否可"原路返回"？**
   - A. 只能向前 —— 工作量小，叙事更纯粹。 *(推荐 MVP)*
   - B. 可以回头补给 —— 自由度高，但需要做"已通过营地"的状态保存。

**核心挑战是什么？**：
  - A. 生存，需要物资抵御寒冷、饥饿，敌人只是威胁的一部分。
  - B. 战斗，一切都是为了打败昼伏夜出的怪物。
